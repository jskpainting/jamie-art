## 1. Pop-ups that can't scroll

**Cause.** `components/ui/dialog.tsx` → `DialogContent` has no max-height and no
overflow rule. Each dialog has to opt in. The painting form did; the **gallery
edit** dialog (`components/admin/section-form-dialog.tsx`, the pencil on
`/admin/portfolio`) did not, and with a cover image + focal-point picker it is
taller than a phone screen. The Move / "Also show in" dialog, contact dialog,
passkeys dialog and section-edit button have the same latent problem.

**Fix (one place).** In `DialogContent`: `max-h-[calc(100dvh-2rem)]
overflow-y-auto` plus `flex flex-col` so every dialog scrolls; keep the footer
inside the scroll area (simplest, no sticky-footer edge cases). Remove the
now-redundant per-dialog `max-h-[90vh] overflow-y-auto` overrides so there is
one rule. `dvh` not `vh` so the iOS keyboard/toolbar doesn't clip it.

Files: `components/ui/dialog.tsx`, `painting-form-dialog.tsx`,
`event-form-dialog.tsx`, `bulk-upload-client.tsx`, `media-picker-dialog.tsx`
(drop overrides).

## 2. Uncategorized slug editable

**Why it's locked today.** The slug `uncategorized` is the app's "holding
bucket": public pages 404 it, `/portfolio` hides it, the dashboard orphan
banner links to it, bulk upload defaults to it, and the Postgres function
`delete_section_safe` moves paintings into it and **raises if it doesn't
exist**. The owner has already renamed the title to "Archives (2018-2021)" and
wants it to be a normal gallery.

**Design — no migration.**
- Remove the lock in `section-form-dialog.tsx` and in `updateSection`
  (`lib/actions/sections.ts`). Revalidate both the old and new slug paths.
- `deleteSection`: before calling the RPC, ensure a section with slug
  `uncategorized` exists (insert `{slug:'uncategorized', title:'Uncategorized',
  sort_order: 999}` if missing). The bucket re-appears only when a gallery is
  deleted with paintings in it. Toast copy: "moved to Uncategorized".
- Dashboard banner / bulk-upload default already degrade to nothing /
  first section when the slug is absent. No change needed.
- **Effect the owner must know:** the moment the slug is changed (e.g. to
  `archives`), that gallery and its 16 paintings become **public** at
  `/portfolio/archives` and appear on `/portfolio` and in the sitemap. That
  is the point, but it's a live-site change.

## 3. Medium + Size dropdowns with "Other", recent-first, managed in Settings

**Storage.** New table (migration, applied by the owner):

```sql
create table if not exists field_options (
  id uuid primary key default gen_random_uuid(),
  field text not null check (field in ('medium','dimensions')),
  value text not null,
  last_used_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  unique (field, value)
);
alter table field_options enable row level security;
create policy "auth all field_options" on field_options for all using (auth.role() = 'authenticated');
-- seed from what's already on the paintings, recency = newest painting using it
insert into field_options (field, value, last_used_at)
select 'medium', trim(medium), max(created_at) from paintings where coalesce(trim(medium),'') <> '' group by 2
on conflict do nothing;
insert into field_options (field, value, last_used_at)
select 'dimensions', regexp_replace(trim(dimensions), '\s+', '', 'g'), max(created_at) from paintings where coalesce(trim(dimensions),'') <> '' group by 2
on conflict do nothing;
```

Gated by a new `fieldOptions` capability in `lib/schema-capabilities.ts`.
**Fallback before the SQL runs:** derive the lists from `paintings` (distinct
values, recency = newest painting using each) so the dropdowns work on day one;
only "remove from list" needs the table.

**Normalisation** (so `12" x 12"` and `12"x12"` are one entry): trim, collapse
whitespace, `×`→`x`. Stored/displayed in the owner's existing form `12"x12"`.

**Server** `lib/actions/field-options.ts`: `getFieldOptions()` (both lists,
recent-first, with in-use counts), `touchFieldOptions({medium, dimensions})`
(upsert + `last_used_at = now()` — called by the form after a successful save
and by bulk upload once per distinct value), `removeFieldOption(field, value)`
(does not touch paintings), `addFieldOption(field, value)`.

**UI** `components/admin/option-select.tsx`: native `<select>` (same look as
the Status select, works on phones) listing the options recent-first plus
**"Other…"**. Choosing Other swaps to a text `Input` with a small "Back to
list" link. If the current value isn't in the list (old painting, custom
value) it starts in "Other" mode showing the value. Used in
`painting-form-dialog.tsx` and in each bulk-upload card
(`bulk-upload-client.tsx`) — bulk upload also gets an "apply to all" for
medium since 74% of paintings share one.

**Settings card** "Painting details lists" (`app/admin/(authed)/settings/
field-options-card.tsx`): two columns, *Medium* and *Size*; each row shows the
value, "used on N paintings", and an ✕ (confirm if N > 0: "Paintings keep
their value; it just leaves the list"). Add box at the bottom of each column.
If the SQL hasn't run, the card shows the standard setup message.

## 5. AR models — automatic, no AI needed

**Key finding.** The "see it on your wall" model is not AI-generated. It is a
flat rectangle at the painting's real size with the photo as its texture
(`scripts/generate-ar-model.mjs`: ~150 lines of geometry + `sharp` resize).
Generation is deterministic, ~2–4 s, and needs only the image and the
`dimensions` text. A model router / Gemini / NVIDIA would add cost, latency and
a failure mode for zero benefit. The existing `lib/ai/router.ts` (already a
port of the BarLogic router) stays for the story writer.

**Design.**
- `lib/ar/build-glb.ts` — pure GLB builder (moved from the script).
- `lib/ar/generate.ts` — `generateArModel(paintingId)`: fetch painting, parse
  size, fetch image, `sharp` → JPEG (long side 2048, q 90 — up from 1400/86,
  "no compromise"), build GLB, upsert to `ar-models/<id>.glb`. `sharp` is
  already bundled by Next (0.34.5) so nothing new to install; runs on Vercel.
- **Trigger:** in `createPainting`, `updatePainting` and `bulkCreatePaintings`,
  after the DB write succeeds, `after(() => generateArModel(id))` from
  `next/server` — runs after the response is sent, so saving stays fast.
  Skips silently when there is no image or no parseable size; regenerates when
  the image or size changed.
- Admin visibility: painting list row shows a small "3D ready" / "No 3D yet"
  chip; a `regenerateArModel` action behind a "Rebuild 3D model" button in the
  painting dialog; Show-cards page gets "Generate missing (N)".
- Scripts become thin wrappers over `lib/ar`.
- **Backfill now:** run the batch for the 18 eligible paintings. The 3 without
  sizes are already in `docs/ACTION_ITEMS.md` for the owner to measure.
